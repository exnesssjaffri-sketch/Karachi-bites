STUDENT COPY

Read this first. This is not a normal assignment. It simulates real freelance work: a real-sounding client, fixed

deadlines, unclear requirements, and changes that arrive while you are working. There is no single correct

solution. You are graded on whether you deliver something a real client could actually use, and on whether you

understand what you built.

1. How this project works

  You are a freelance developer. Your teacher plays the client, Mr. Farooq. He is busy, sometimes vague, and

occasionally changes his mind. Talk to him the way you would talk to a paying client.

 Ask questions. The brief below is deliberately incomplete. Guessing wastes the client's money; asking early

saves it. Good questions are marked positively.

 You may use Cline and ChatGPT. But you are responsible for every line that ships. At the review you will be

asked to explain your code and to change it live.

 Expect change. Requests will arrive during the 21 days, as in real life. How you respond (estimate, negotiate,

deliver, communicate) is part of your mark.

 Deadlines are real. If you will miss a milestone, tell the client before the deadline with a plan. A late milestone

with no warning costs 5 marks.

 Status updates: send at least 3 short updates per week to the client group (3 lines: done, doing next, blocked).

4. Requirements

Must have (the client will not launch without these)

 ID

Requirement

F1

Menu page: items grouped by category, showing name, price, tags and availability.

F2

Search box and filters (veg, spicy, maximum price) that work together.

F3

Cart: add, remove, change quantity. Shows subtotal, delivery charge and total in Rs.

F4

Cart survives a page refresh.

F5

Checkout form: name, phone (valid Pakistani mobile number), address, branch, notes. Clear validation messages.

F6

Placing an order saves it on the server and returns a unique order ID.

F7

Tracking page: customer enters order ID and phone number and sees the current status.

F8

F9

Staff login. Admin pages and admin API routes are protected.

F10

Admin dashboard: list orders, filter by branch and date, update status.

F11

Fully usable at 360 px width. No sideways scrolling. Buttons easy to tap.

F12

Deployed publicly (front end and back end) with code on GitHub. Data must not disappear when the server restarts or

redeploys.

6. Constraints

 Area

Rule

Performance

Home page loads in under 3 seconds on Chrome DevTools "Slow 3G" and weighs under 1.5 MB.

Technology

Vanilla HTML, CSS, JavaScript and Node/Express. No front-end framework unless the client approves it in

writing during M0.

Data

You choose where data is stored (file, SQLite, hosted database). It must survive restarts. Explain the

choice in DECISIONS.md.

Security

No secrets in the repo (use environment variables). Passwords are hashed. All totals are calculated by the

server.

Git

At least 25 meaningful commits with readable messages. Commit small and often.

Browsers

Latest Chrome on Android and on desktop.

AI tools

Allowed. Keep AI_LOG.md (see below). You must be able to explain everything you submit.
